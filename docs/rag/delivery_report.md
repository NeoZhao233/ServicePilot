# 可插拔决策 RAG 交付状态

已完成 DeepSeek 证据评分、四态充分性判断、规则优先的来源/类别/日期检查和最多两次针对性补检索。统一 Pydantic Schema 与 EvidenceEvaluator 接口隔离模型；Jev 当前不可用时明确报错，只有显式配置才回退 DeepSeek。工作流复用现有 Hybrid RAG、LangGraph、Trace 与人工降级，原始 RAG 仍为默认模式。相同 ID 的不同政策块在新模式启动时拒绝加载，防止 RRF 先合并而隐藏版本冲突。

实网验证无需 Jev 密钥，共使用用户授权额度中的 81/95 次 DeepSeek 请求。17 条同配置冻结样本完成 B0–B3 对照；7 条复杂样本中，6 条完成且状态判断符合标注，1 条由于模型推理耗尽 8192 输出 token 而安全失败。早期两个不同配置的失败样本也保留在观测中，未重试。详细数值、不同版本和失败原因见 `ablation_report.md` 与 `evaluations/results/pluggable_rag/ablation_status.json`。

全部 189 项测试通过，Ruff 通过。验证覆盖：严格 ID/分数 Schema、提供商选择与回退、真客户端复用和 Trace 用量、模型超时后的并发租约、缺失信息纠错、重复检索停止、元数据门禁、动态任务安全交接，以及预算和实验覆盖统计。测试仅有一条现存 Starlette/AnyIO 依赖弃用警告。

仍需独立的最终回答评审才能填写回答正确率和无依据政策承诺次数；API 未返回费用，真实成本未知。复杂问题可能耗尽模型推理预算，系统会停止并安全降级，因此不能宣称所有问题均被模型成功判断。评分没有启用无校准阈值，未来 Jev 接入需实现适配器、独立校准和回归。使用方式见 `README.md`，原始审计及基线见 `architecture_audit.md`。
